# 接入新来源 / 新栏目

把一个新站点或新栏目接进农大门户的数据管道。管道是：

```
sites.json（来源清单，仓库权威）──▶ Actions 每 2h 抓取 crawl.mjs ──▶ data/feed|<id>__<key>.json
                                                              └──▶ AI 加工 enrich.mjs ──▶ 面板/MCP
```

**核心原则：先探测、只报告、等用户确认，再动仓库。** 每条结论都要有实测依据 —— 不许凭"看起来像"下判断。

---

## 0. 先问清楚（缺哪个问哪个，不要猜）

- **名称**：显示给用户看的中文名（如「浙大环境与资源学院」）
- **网址**：优先要**列表页** URL；只给首页也行，但要先找到列表页
- 是**新站点**，还是在**已有站点下加一个栏目**？
- 目标站点是否需要登录 / 是否只对校内 IP 开放（这决定能不能自动抓，见第 6 步）

---

## 1. 探测：先跑 `probe.mjs`，不要只靠肉眼看网页

```bash
node tools/scraper/probe.mjs "<网址>" --cols 12
```

它输出：站点标题 / CMS 判定与依据 / 每个候选栏目（栏目号 + 条目数 + 页数 + 样例 + 正文抽样）/ 结论 / 可直接粘进 sites.json 的片段。

**为什么必须用它**（2026-09-14 实测教训）：肉眼读网页会误判 —— 同一站点先被判「需登录」（其实是首页有个「登录」链接），又被判「接不了：仅限校内 IP」（其实只有部分栏目受限）。probe 会逐栏目抓列表页、查 `<input type=password>`、识别苏迪/博达的拦截页（HTTP 200 的「提示信息」页），结论才可靠。

需要的环境：Node ≥ 18（用内置 fetch）。probe 只读不写，可以放心跑。

### CMS 类型与接入成本

| cms | 识别特征 | 接入成本 |
|---|---|---|
| `boda` 博达 | 文章 `/art/<年>/<月日>/art_<栏目>_<文章>.html`；列表 `/col/col<id>/index.html` + `dataproxy.jsp`（unitid/webid） | **只加配置** |
| `sudy` 苏迪（南京苏迪） | 列表 `/<栏目号>/list.htm`（翻页 `list2.htm`…，可能 301 到 `list.psp`）；详情 `/<年>/<月日>/c<栏目>a<文章>/page.htm`；正文容器 `wp_articlecontent`；条目在 `div#wp_news_w<N> > ul.news_list` | **只加配置**（解析器已内置） |
| `news-custom` | 校新闻网 `news.cau.edu.cn`：列表 `<path>new/index.htm`，文章是 hash 页 | **只加配置** |
| `portal` | 统一门户 `one.cau.edu.cn`，**必须登录** | 已有（跑在本机已登录会话里） |
| 其他 | 纯 JS 渲染 / 反爬 / 非常规分页 | **要新写解析器**（改 `tools/scraper/`），或如实说接不了 |

**栏目 id 怎么找**：博达看文章链接 `/art/2026/9/13/art_31131_1134601.html` 中间那段数字（31131）；苏迪看列表 URL 的 `/<栏目>/list.htm`（**数字或字母都可能是 id**，如 `xxgg`）。

## 2. 报告：给用户一张逐栏目表，然后停下等确认

```
站点：浙大环境与资源学院（http://www.cers.zju.edu.cn/cercn）
CMS ：苏迪 sudy（依据：列表 /xxgg/list.htm、正文容器 wp_articlecontent）
结论：✅ 能直接接（解析器已内置，只加配置，不用写代码）

| 栏目 | id/path | 首页条目 | 页数 | 最新一篇 | 正文抽样 | 备注 |
|---|---|---|---|---|---|---|
| 信息公告 | xxgg | 14 | 21 | 2026-09-11 | 2904 字 | 建议接 |
| 新闻动态 | 38989 | 14 | 59 | 2025-09-12 | 342 字 | 建议接 |
| 学生动态 | xsdt | 14 | 7 | 2019-11 | 950 字 | ❌ 停更 |
| 学术交流 | 39441 | 10 | 26 | 2019 | 0 字 | ❌ 停更 + 正文跳外站需 WebVPN |
```

表格里必须写清：**建议接的**、**不建议接及原因**（停更 / 静态页 / 图集 / 多个栏目指向同一列表 / 受访问限制）。
结论只有三种：**✅ 能直接接** / **⚠️ 需要写解析器（说明工作量）** / **❌ 接不了（说明原因）**。

**两条硬规则：**

1. **发现解析器缺陷 → 先报告、先单独修，不要带着 bug 写配置。** 例：苏迪列表页的头部导航里可能有指向文章页的菜单链接（浙大环资的「师资队伍」），解析器若不限定列表容器，**每个栏目都会多出一条假条目**并污染「要闻」。这种情况先修解析器（`tools/scraper/parse-sudy.mjs` 的 `LIST_CONTAINER`），并回归验证已接入站点条目数不变。
2. **权限要逐栏目、逐文章验。** 同一个站可能「栏目 A 公开 / 栏目 B 限校内 IP / 某篇文章要登录」——解析器对受限条目只留标题、不写正文，这是预期行为，不是抓取故障。

## 3. 写 `sites.json`（用户确认后）

仓库根目录 `sites.json` 是**来源清单的单一事实源**（面板的「栏目频道管理」直接读它，配置一推就生效，不必等抓取）。

```json
{
  "id": "zju_cers",
  "name": "浙大环境与资源学院",
  "baseUrl": "http://www.cers.zju.edu.cn/cercn",
  "cms": "sudy",
  "group": "external",
  "columns": [
    { "id": "xxgg", "key": "notice", "name": "信息公告" },
    { "id": 38989, "key": "news", "name": "新闻动态" },
    { "id": 38991, "key": "research", "name": "学术展台" }
  ],
  "note": "苏迪 CMS，2026-09-14 探测后接入。全站公开（无 IP 限制、无登录）。未收录：学生动态 xsdt(最新 2019)、学术交流 39441(正文跳 zhfw.zju.edu.cn 需 WebVPN)；rcpy 与 xxgg 指向同一列表，只收一次。"
}
```

- `id`：短英文标识。**会出现在 `data/feed/<id>__<key>.json`，定了不要再改。**
- `baseUrl`：可以带路径（如 `/cercn`）；站点条目按 **host** 归属，所以 baseUrl 的 host 必须是该站自己的域名。
- `cms`：见上表。
- **`group`：来源分组 —— `"campus"` 校内其他（农大各站，缺省值）/ `"external"` 校外来源（外校）。**
  面板首页「栏目频道」分成 校内平台（统一门户）/ 校内其他 / 校外来源 三组；「要闻」二级页同样三组。
  **非本校来源（浙大、北大、中科院某所…）必须显式写 `"group": "external"`** —— 用户关注外校是为了保研等长期用途，
  不能让它们混进农大自己的通知里（2026-09-14 用户明确要求）。认不出归属的条目按域名兜底：
  `*.cau.edu.cn` 算本校，其余算校外。
- `columns[].id`：栏目号（博达/苏迪都是数字或字母）；`key`：短英文（feed 文件名用，站内唯一）；`name`：中文显示名。
- **`note`：把探测结论写进去** —— 哪些栏目没接、为什么、有什么预期内的限制。后来的人（包括未来的你）靠它省一次探测。
- 给**已有站点加栏目** → 追加到该站 `columns`，不要新建站点条目。
- ⚠️ **不要写 `localOnly`**：这个字段**代码里没有实现**（旧草稿骗过人）。只能本机抓的站点请看第 6 步。

改完自检：

```bash
node -e "const c=require('./sites.json');console.log(c.sites.map(s=>s.id+':'+s.columns.length).join(', '))"
```

## 4. 空跑验证（**必做；不碰 `data/`**）

用**候选配置 + 临时目录**空跑，绝不用默认的 `--data-dir data`（那会用手工抓的本地数据覆盖 Actions 的权威数据）：

```bash
# 1) 把新站点单独抄进 tools/tmp-sites-<id>.json（同时带上 1 个已接入站点做回归）
# 2) 空跑：列表翻 2 页 + 每栏抓 2 篇正文
node tools/scraper/crawl.mjs --sites tools/tmp-sites-<id>.json --pages 2 --articles 2 --delay 400 --data-dir <工作区绝对路径>\tools\tmp-data-<id>

# 3) 检查落盘结果（导航污染 / 无日期 / 有正文）
node -e "const fs=require('fs');const d='<上一步的临时目录>/feed';for(const f of fs.readdirSync(d)){const j=JSON.parse(fs.readFileSync(d+'/'+f,'utf8'));console.log(f.padEnd(26),'条目',j.items.length,'| 无日期',j.items.filter(i=>!i.date).length,'| 有正文',j.items.filter(i=>i.article).length)}"
```

**通过标准**：新栏目 `错误 0`、条目数与 probe 一致、`无日期 0`、正文抽样非空、已接入站点条目数不变。
**收尾**：删掉临时配置、临时数据目录、`tools/tmp-*.mjs`（本项目对过程文件零容忍）。

常见坑（多数已在解析器里处理，出问题时照此排查）：

| 现象 | 原因 / 处理 |
|---|---|
| 每个栏目都多出同一条假条目 | 列表页头部导航里有文章链接 → 解析要限定列表容器（苏迪：`div#wp_news_w<N>` / `ul.news_list`） |
| 抓到的是登录页 / 「提示信息」页 | 拦截页也返回 HTTP 200 → 必须检测（`blockedReason()`：仅限校内 IP / 需登录 / 栏目不存在） |
| 标题乱码 | 站点是 GBK/GB2312 → 按该编码解码 |
| 相对链接 404 | 用 `new URL(href, 列表页最终 URL)` 解析，别拿站根做字符串拼接 |
| 正文 0 字 | 图片海报（`is_image_only`）或表格页；不是 bug，但要如实报告 |
| 个别条目跳到别的域名 | 属正常（如招生/人事通知挂在学校门户）；条目仍会展示，只是按 host 归属频道 |
| 分页停不下来 / 页数离谱 | 只统计**本栏目**的 `listN.htm`；翻到空页或重复内容就停 |
| 站点只有 HTTP（无 HTTPS） | 照写 `http://`；probe 会自动在 https 失败时退回 http |

## 5. 推送（**顺序：先私有仓 → 再公有仓**）

- 权威私有仓 `ZBber-lab/cau-portal`（含 data/、SPEC）；开源公有仓 `ZBber-lab/cau-portal-open`（不含 data/、SPEC、校徽素材）。
- **必须先把私有仓推完、核验通过，再动公有仓**（用户明确要求）。
- `data/` 是 Actions 的产物：**推送代码时不要覆盖远端 `data/`**。
- 本机 `git push`/`clone` 到 github 经常 443 超时 → 用 **GitHub Git Data API**：`POST /git/blobs` → `POST /git/trees`（带 `base_tree`）→ `POST /git/commits`（author/committer `cau-portal-bot`）→ `PATCH /git/refs/heads/main`（`force:false`）。
- **只推真正变化的文件**：对每个待推文件算 git blob sha（`sha1("blob " + 字节数 + "\0" + 内容)`），与 `GET /git/trees/main?recursive=1` 里的 sha 逐字节比对，只把不同的放进新 tree。
- 推完**必须用 API 复核**：重新拉 `GET /git/trees/<新commit>?recursive=1`，确认白名单文件 sha 与本地一致；必要时再取一次文件内容确认。
- 提交信息格式：`plugin: phase X step Y <一句话>` 或 `tools: <一句话>`。

## 6. 运行环境验证：**本机成功 ≠ 线上成功**

Actions 的 runner 在境外。抓国内教育网站点时，**同一次运行里有的列表页成功、有的直接 `TypeError: fetch failed`**（2026-09-14 实测：浙大环资 3 个栏目线上 0 条、本机 28/28/18 条；浙大地科 5 个列表页里 3 个挂）。

做法：

1. 推完配置等下一轮 Actions（每 2h，北京 8:00–23:00），然后**读远端结果**：
   ```bash
   # data/feed/<id>__<key>.json 的 items 长度、data/index.json 里该站点的 items
   ```
2. 若线上 0 条而本机正常 → 判定为**跨网链路问题**，不是解析器问题。这时：
   - 拉该轮 Actions 日志看具体错误（`! 列表页 1 失败: … (ETIMEDOUT/ECONNRESET)…`）；抓取脚本对失败 URL 会重试 4 次、超时 30s，失败信息带底层原因。
   - **如实告诉用户**：这个站点自动抓取不稳；数据要么本机回填（`crawl.mjs` + `enrich.mjs` 后推 `data/`），要么等链路好转。
   - 不用担心丢数据：增量合并会保留历史条目（某轮抓挂不会清空已有 feed）。
3. 不要为了"看起来有数据"而手工推假的空/占位 feed。

## 7. 面板可见性与告知用户

- 来源清单一推，面板**立刻**能看到：设置 → 智能与数据 → **栏目频道管理** 里出现新来源，标「**尚未抓取**」；抓完自动补条目数。**不需要重装插件、不需要重启**（客户端配置驱动；改了 `lib/` 才需要刷新/重启）。
- 首页「栏目频道」按 校内平台 / 校内其他 / 校外来源 分三组；**「要闻」在首页只占一行入口**（带各组条数），点进去才展开完整列表（含三组）。「今日要览」与未读计数**包含**校外来源，只是外校条目带「校外」标记。
- 新条目的 AI 摘要/分类/重要度/deadline 按每轮 **8 篇**排队补，会陆续出现。
- **明确告诉用户**：预计什么时候能在面板看到、大约多少条、有没有受限/停更的栏目没接。
